# Operator Handoff — Astrum Phase I Lead Agent

**Audience:** BD users, Zak, Catherine, future delivery team.
**Status:** Draft, MVP-stage. Will be expanded post Phase 4.

---

## 1. What this system does
Continuously scans free public sources for US biotech/pharma companies signalling a move into Phase I clinical development, scores them for Astrum fit and timing, and surfaces a ranked, source-linked outreach queue inside Salesforce/Orbit.

## 2. What it does NOT do
- Send any outbound communication.
- Scrape LinkedIn or any paid source.
- Modify Account or Lead records outside its own custom objects without human approval.
- Operate in production without explicit sign-off.

## 3. Daily BD workflow
1. Open **Signals Inbox** Lightning app in Salesforce.
2. Filter by `Priority_Band__c = Hot`.
3. Click into a Target Company.
4. Read the **BD Brief** (generated by Agentforce — every claim is cited).
5. Verify the 2–3 most recent Signals by clicking their Source URLs.
6. Accept or dismiss the recommended BD Action.
7. Log outreach activity on the BD_Action__c record.

## 4. How to interpret scores
| Field | Meaning |
|---|---|
| Phase_I_Readiness_Score__c | How close is this company to Phase I, by stored signals (deterministic). |
| Astrum_Fit_Score__c | Modality + TA + stage alignment with Astrum priorities (see breakdown below). |
| Timing_Score__c | Recency of qualifying signals. |
| Source_Confidence_Score__c | Average tier of Sources backing this company. |
| Overall_Priority_Score__c | 0.40·PhaseI + 0.25·Fit + 0.20·Timing + 0.15·SourceConf |

Bands: Hot ≥75 · Warm 55–74 · Watch 35–54 · Cold <35

### Astrum Fit Score breakdown
`Astrum_Fit_Score = (modality_score × 0.40) + (TA_score × 0.40) + (stage_score × 0.20)`

**Modality priority list** (full points if matched): Small molecule, ADC, Peptide, Oligonucleotide, Biosimilar  
**TA priority list** (full points if matched): Oncology & Hematology, CNS, Immunology, Cardiometabolic  
**Stage sweet spot** (full points): Series A, B, or C  

Half points if unknown; zero if confirmed non-match. All three fields stored on Target_Company__c and compared deterministically — no LLM re-scoring..

## 5. How to handle a suspect Signal
- Click the Source URL. Read the underlying article/filing.
- If the Signal misrepresents the source → set `Status__c = Rejected`, leave a comment.
- If the Source URL is broken → set `Source__c.Verification_Status__c = Broken`.
- If the company is not actually US-based → set `Country__c` correctly; the next nightly score run will re-band.

## 6. How to override the agent
- Any field on Target_Company__c and Signal__c can be edited manually.
- Manual edits are preserved across ingestion runs (worker uses upsert on external Id, not destructive write).
- To remove a company entirely → set `Status__c = Archived`.

## 7. Operating limits & known issues
- LinkedIn is not ingested. Key-hire signals depend on press releases only in MVP.
- Google News RSS can introduce duplicate Signals across slightly different headlines — dedupe is hash-based and may miss paraphrased duplicates. Manual merge expected occasionally.
- Worker pause: contact Amit. No self-service pause control in MVP.

## 8. Incident response
| Symptom | First step |
|---|---|
| No new Signals in 24h | Check worker telemetry (Amit) |
| Hot band looks wrong | Check most recent Score_Snapshot__c reasoning JSON |
| Agent brief includes wrong fact | Set Agent_Audit__c.hallucination_flag = true; notify Amit |
| Source URL broken | Field auto-flagged nightly; manually update if needed |
